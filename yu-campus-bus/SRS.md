# BUS@YU — Software Requirements Specification (SRS)

- 문서 버전: 2.1
- 작성일: 2026-08-29
- 대상: 영남대학교 경산캠퍼스 교내 이동 웹앱/PWA
- 제품명: **BUS@YU**
- 기준 지도: OpenStreetMap + Leaflet
- 기준 시간표: 사용자 제공 2026학년도 2학기 순환버스 배차표

---

## 1. 문서 목적

본 문서는 BUS@YU의 기능, 데이터, UX, 수익화, 개인정보, 서버 API, 품질 기준 및 단계별 구현 범위를 정의한다.

제품의 핵심 목표는 다음과 같다.

1. 캠퍼스 내 목적지까지 **도보 / 도보+순환버스** 경로를 비교한다.
2. 실제 차량 GPS를 확보하지 못한 상황에서도 **시간표 기반 ETA**를 제공한다.
3. 사용자가 명시적으로 동의하면 탑승 중 휴대폰 위치를 일시적으로 공유하여 **크라우드 기반 버스 위치 보정**에 활용한다.
4. 탑승자의 자발적 신고로 **버스 혼잡도**를 제공한다.
5. 공유 킥보드/PM의 **확인된 주차 가능 지점**을 지도 레이어로 제공한다.
6. 카카오맵 계열의 밀도 높은 지도 UX를 참고하되, 독자적인 UI로 구현한다.
7. Ezoic 광고를 적용하되 길찾기·승하차 안내를 방해하지 않는 수준에서 수익성을 확보한다.
8. 메인 BUS@YU 화면과 유용한 사이트 화면을 좌우 2페이지 구조로 제공한다.
9. 유용한 사이트를 운영자가 파일로 수시 등록하고, 오늘/이번달 익명 고유 사용자 수를 제공한다.

## 2. 범위

### 2.1 포함 범위

- 영남대학교 경산캠퍼스 지도
- 1노선(인문계), 2노선(자연계) 노선 및 정류장
- 순환버스 배차표
- 시간표 기반 차량 예상 위치
- 정류장별 ETA
- 현재 위치 기반 경로 탐색
- 도보와 버스 결합 경로 비교
- 승차/하차 알림
- PWA 설치 지원
- 광고 슬롯 및 Ezoic 연동 어댑터
- 익명 크라우드 버스 위치 공유
- 사용자 신고형 혼잡도
- 공유 킥보드/PM 주차 존 레이어
- 최소한의 실시간 API 서버
- 좌우 2페이지 화면 전환
- 유용한 사이트 4열 아이콘 그리드
- 오늘/이번달 익명 고유 브라우저 사용자 집계
- 유용한 사이트 페이지 전용 하단 광고

### 2.2 제외 범위

다음은 데이터나 제휴가 확보되기 전까지 지원하지 않는다.

- 학교 또는 운수 운영 주체의 실제 버스 GPS 피드
- 통신사 기지국 기반 버스별 승객 수/혼잡도
- 공유 킥보드 업체의 실시간 기기 좌표/잔여 대수
- 결제/대여 시작/반납 처리
- 공식 교통카드 연동
- 백그라운드에서 OS가 보장하는 네이티브 수준 위치 추적

## 3. 용어 정의

| 용어 | 정의 |
|---|---|
| ETA | Estimated Time of Arrival. 예상 도착 시각/남은 시간 |
| 시간표 ETA | 배차시각 + 도로망 예상 주행시간 + 정차시간으로 계산한 ETA |
| Crowd ETA | 탑승자의 동의 기반 위치 샘플로 시간표 ETA를 보정한 값 |
| PM | Personal Mobility. 전동킥보드 등 개인형 이동장치 |
| 승차 정류장 | 추천 경로에서 순환버스를 타는 정류장 |
| 하차 정류장 | 추천 경로에서 순환버스를 내리는 정류장 |
| Guidance | 승차/하차를 위한 실시간 안내 모드 |
| 세션 | 브라우저 탭/웹앱 실행 단위. `sessionStorage` 생명주기를 기본으로 함 |

## 4. 사용자 유형

### 4.1 일반 학생/교직원

- 현재 위치에서 목적지 검색
- 버스/도보 비교
- ETA 확인
- 승하차 안내
- 킥보드 주차 존 확인

### 4.2 버스 탑승 사용자(자발적 기여자)

- `탑승했어요` 이후 익명 위치 공유 동의 가능
- 현재 혼잡도 신고 가능
- 기여 데이터는 짧은 TTL 후 자동 폐기

### 4.3 운영자

운영자는 서버 파일/코드 설정 방식으로 데이터를 관리한다. 별도 관리자 웹페이지는 현재 요구사항에 포함하지 않는다.

- `data/useful-sites.json`: 유용한 사이트 등록/수정/순서/노출 여부
- 배차표/정류장/PM 존: 코드 또는 향후 별도 데이터 파일
- 광고 placement: `index.html`의 광고 설정

사이트 목록은 서버가 요청 시 JSON 파일을 다시 읽으므로 파일 저장 후 재시작 없이 반영 가능해야 한다.

## 5. 기능 요구사항

### FR-001 지도

- OpenStreetMap 타일을 표시한다.
- 캠퍼스 중심으로 초기 화면을 설정한다.
- 확대/축소/현재 위치/캠퍼스 전체 보기 기능을 제공한다.
- 지도 저작권 표기를 유지한다.

### FR-002 순환버스 노선

- 1노선과 2노선을 구분된 색으로 표시한다.
- 각 정류장을 번호가 있는 마커로 표시한다.
- 정류장 팝업에 다음 정보를 표시한다.
  - 노선
  - 정류장 번호
  - 정류장명
  - 건물 코드
  - 위치 설명
  - 주요 이용 시설
- 동일 위치에 두 노선이 정차하는 경우 이를 시각적으로 구분한다.

### FR-003 배차표

아래 시간표를 기준으로 한다.

- 08:00~10:50: 10분 간격
- 11:00, 11:20, 11:40
- 점심: 운행 없음
- 13:00~17:40: 20분 간격
- 서문 순환지점: 5분 정차

운행 요일/휴일 조건은 신뢰 가능한 원천 데이터가 없으므로 임의 생성하지 않는다.

### FR-004 시간표 기반 ETA

실제 GPS가 없는 경우 다음을 사용한다.

1. 기준 출발 시각
2. OSRM 도로 경로의 구간 예상 운행시간
3. 서문 5분 정차
4. 정류장 순서

화면에서는 반드시 `예상`, `시간표 기준`, `실제 GPS 아님` 중 하나 이상의 표시를 제공한다.

### FR-005 크라우드 기반 위치 보정

- 사용자가 버스에 탑승한 뒤 별도 동의한 경우에만 위치를 서버로 전송한다.
- 기본값은 **공유 안 함**이다.
- 위치 데이터는 버스 위치 추정에 필요한 최소 필드만 사용한다.
- 위치 샘플은 서버에서 최대 2분 TTL로 유지한다.
- 영구 사용자 계정/실명/전화번호와 결합하지 않는다.
- 실시간 API는 개별 사용자 좌표 목록을 공개하지 않고 **노선별 집계 위치**만 반환한다.
- 크라우드 표본이 없으면 시간표 ETA로 자동 폴백한다.

### FR-006 혼잡도

탑승 사용자가 다음 중 하나를 신고할 수 있다.

- 여유
- 보통
- 혼잡
- 만석

표시 규칙:

- 응답이 없으면 `정보 없음`으로 표시한다.
- 앱 사용자 신고와 실제 전체 승객 수를 동일하게 표현하지 않는다.
- `최근 N명 신고`, `최근 업데이트 시각`을 표시할 수 있어야 한다.
- 신고는 일정 시간 후 자동 만료한다.

### FR-007 목적지 검색

- 정류장명, 건물명, 건물 코드, 별칭으로 검색할 수 있다.
- 지도 클릭으로 임의 목적지를 지정할 수 있다.
- 존재하지 않는 건물을 임의 생성하지 않는다.

### FR-008 경로 탐색

최소 다음 후보를 계산한다.

1. 직접 도보
2. 도보 → 1노선 → 도보
3. 도보 → 2노선 → 도보

각 후보에 다음을 제공한다.

- 총 예상 시간
- 도보 거리
- 승차 정류장
- 예상 승차시각/대기시간
- 하차 정류장
- 버스 예상 탑승시간
- 단계별 안내

가장 빠른 후보를 우선 표시한다.

### FR-009 승하차 안내

버스 결합 경로에서 `승·하차 알림 시작`을 제공한다.

상태:

1. `to_board`: 승차 정류장으로 이동
2. `waiting`: 승차 정류장 도착/대기
3. `riding`: 탑승 중
4. `completed`: 하차 완료

기본 임계값:

- 승차장 접근: 220m
- 승차장 도착: 70m
- 버스 ETA 임박: 3분
- 하차장 접근: 350m
- 하차 직전: 120m

알림 채널:

- 화면 내 안내 바
- 브라우저 Notification(허용 시)
- 진동(지원 시)
- 알림음(사용자 상호작용 후 가능한 경우)

### FR-010 PWA

- Web App Manifest 제공
- Service Worker 제공
- 주요 정적 자산 캐시
- HTTPS/localhost에서 설치 및 위치 권한 사용

백그라운드 위치 추적은 브라우저/OS 제약을 받으므로 네이티브 앱 수준을 보장하지 않는다.


### FR-011 좌우 2페이지 셸

- 1페이지는 `BUS@YU` 메인 지도/길찾기 화면이다.
- 2페이지는 `유용한 사이트` 화면이다.
- 상단 페이지 전환 탭을 제공한다.
- 모바일에서 수평 스와이프를 지원한다. 단, 메인 지도 위 제스처는 Leaflet 지도 이동과 충돌하지 않도록 강제로 가로채지 않는다.
- 메인에는 우측 페이지 이동 핸들을 제공한다.
- 페이지 전환 시 지도/안내 상태를 유지한다.

### FR-012 유용한 사이트 그리드

- 한 행에 4개 아이콘을 표시한다.
- 아이콘 아래 사이트명을 표시한다.
- 클릭 시 외부 사이트를 새 탭에서 연다.
- 데이터 소스는 `data/useful-sites.json`이다.
- `title`, `url`은 필수이며 `icon`, `description`, `order`, `enabled`를 지원한다.
- `enabled=false` 항목은 노출하지 않는다.
- `order` 오름차순으로 표시한다.
- 운영자는 관리자 페이지 없이 JSON 파일을 직접 수정한다.
- 잘못된 URL 또는 비 HTTP(S) URL은 표시하지 않는다.

### FR-013 사용자 수 표시

- 유용한 사이트 페이지 하단에 `오늘 사용자 수`, `이번달 사용자 수`를 표시한다.
- 기준 시간대는 `Asia/Seoul`이다.
- 계정이 아닌 익명 브라우저 토큰 기준 고유 사용자 추정치로 정의한다.
- 원본 브라우저 토큰은 서버 저장소에 저장하지 않고 해시만 보관한다.
- 통계 블록 바로 아래에 유용한 사이트 페이지 전용 광고 배너를 배치한다.

## 6. 광고/수익화 요구사항

### FR-ADV-001 기본 정책

광고는 앱의 핵심 길찾기 기능을 막지 않아야 한다.

광고 구역은 반드시 `광고` 또는 광고 네트워크가 요구하는 라벨링을 따른다.

### FR-ADV-002 최초 대형 광고

사용자 요구에 따라 **세션 최초 진입 시 1회** 큰 광고 슬롯을 제공한다.

정책:

- 앱 콘텐츠와 광고를 시각적으로 분리한다.
- 즉시 닫기 버튼을 제공한다.
- 현재 위치 요청, 경로 검색 등 사용자의 핵심 행동을 시작하면 자동 축소 가능하다.
- 같은 브라우저 세션에서는 다시 표시하지 않는다.
- 실제 Ezoic 적용 전에는 개발용 placeholder만 출력한다.
- Ezoic/Google 정책에 맞는 승인된 placement 방식만 실제 광고로 교체한다.

### FR-ADV-003 상시 하단 얇은 배너

- 모바일/데스크톱 모두 화면 하단에 얇은 광고 영역을 예약한다.
- 길찾기 전/후 및 승하차 안내 중에도 유지한다.
- 안내 바와 겹치지 않는다.
- 지도 컨트롤, 현재 위치 버튼, 경로 결과 CTA를 가리지 않는다.
- 모바일에서는 50~60px 수준의 최소 예약 높이를 기본값으로 사용한다.
- Ezoic Anchor 사용 시 bottom position을 사용하고 expansion은 비활성화하는 구성을 권장한다.
- 이 광고는 BUS@YU 메인 페이지용이다.

### FR-ADV-004 금지 UX

- 지도 조작 도중 임의 전면 광고 금지
- 승차/하차 경고를 광고가 덮는 행위 금지
- 광고를 닫기 어렵게 만드는 UI 금지
- 광고를 지도 마커/버튼처럼 위장 금지

### FR-ADV-005 Ezoic 구현 방식

프로덕션 설정값이 없으므로 코드에 다음 어댑터를 둔다.

- `ADS_PROVIDER`: `demo` / `ezoic`
- `EZOIC_LAUNCH_PLACEMENT_ID`
- `EZOIC_BANNER_PLACEMENT_ID` 또는 Ezoic Anchor 설정

Ezoic 계정/사이트 승인/placement ID가 없는 환경에서는 가짜 광고 요청을 전송하지 않는다.

### FR-ADV-006 유용한 사이트 페이지 광고

- 2페이지의 가장 아래에 별도 배너 광고 슬롯을 둔다.
- `오늘 / 이번달 사용자 수` 블록 바로 아래에 위치한다.
- 메인 Anchor와 별도의 placement ID를 사용할 수 있어야 한다.
- Ezoic Anchor가 전역 UI인 경우 2페이지에서는 메인 Anchor를 끄고 2페이지 전용 배너를 사용한다.

## 7. 공유 킥보드/PM 요구사항

### FR-PM-001 PM 레이어

지도 레이어 토글에 `킥보드/PM 주차`를 제공한다.

### FR-PM-002 데이터 신뢰도

각 PM 존은 다음 신뢰도 중 하나를 가진다.

- `verified`: 공식 자료로 위치가 확인됨
- `building-relative`: 공식 자료는 있으나 정확한 핀은 건물 단위로만 확인됨
- `community`: 사용자 제보, 검증 필요
- `provider`: 업체 API 제공

신뢰도가 낮은 위치를 정확한 공식 존처럼 표현하지 않는다.

### FR-PM-003 현재 확인된 데이터

현재 공식 자료에서 확인 가능한 항목:

- **상경관 편의점 앞 자전거 거치대**: 전동킥보드 주차 안내가 확인됨.

정확한 위경도는 공식 자료에서 확인되지 않았으므로 건물 중심 또는 OSM 검색 결과를 사용하되 `정확한 핀 현장 확인 필요`를 표시한다.

### FR-PM-004 업체 실시간 대수

업체 공식 API/제휴 데이터가 없는 동안 실시간 대수는 표시하지 않는다.

## 9. API 요구사항

프로토타입 서버 Base URL은 동일 origin의 `/api`를 사용한다.

### POST `/api/telemetry`

목적: 동의한 탑승자의 현재 위치 전송.

검증:

- routeId 허용값 확인
- 캠퍼스 주변 범위 확인
- 좌표/정확도 타입 검사
- TTL 적용

### GET `/api/live-buses`

목적: 노선별 집계된 크라우드 위치 반환.

개별 riderToken/개별 좌표 배열은 반환하지 않는다.

### POST `/api/crowding`

목적: 혼잡도 신고.

### GET `/api/crowding`

목적: 최근 유효 신고 집계.

### GET `/api/useful-sites`

목적: 운영자가 관리하는 활성 사이트 목록을 order 순으로 반환.

### POST `/api/visit`

목적: 브라우저 고유 토큰을 익명 집계에 반영하고 오늘/이번달 수치를 반환.

### GET `/api/visitors`

목적: 오늘/이번달 익명 고유 브라우저 수 반환.

### GET `/api/health`

목적: 서버 상태 확인.

## 10. 개인정보 및 보안 요구사항

### NFR-PRIV-001 명시적 동의

길찾기용 위치 권한과 **크라우드 공유 동의**를 분리한다.

위치 권한을 허용했다고 해서 자동으로 서버 전송하지 않는다.

### NFR-PRIV-002 최소 수집

- 이름, 학번, 이메일, 전화번호 수집 금지
- 방문자 집계용 원본 visitorToken 영구 저장 금지
- 방문자 집계에는 해시값만 저장
- 장기 위치 이력 저장 금지
- 위치 샘플 TTL: 기본 120초

### NFR-PRIV-003 전송

프로덕션에서는 HTTPS 필수.

### NFR-PRIV-004 남용 방지

서버는 간단한 rate limit과 입력 검증을 수행한다.

본 프로토타입은 인메모리 저장 방식이며 운영 배포 전 전문적인 보안 검토가 필요하다.

## 16. 수익화 운영 원칙

1. 최초 대형 노출은 세션당 1회.
2. 하단 배너는 상시 유지.
3. 배너 확장으로 안내 UI를 덮지 않도록 한다.
4. 전면광고/비네트는 기본 비활성 권장.
5. 광고 수익성과 길찾기 완료율을 함께 측정한다.
6. 광고로 인해 `route_search → guidance_started` 전환율이 유의하게 하락하면 광고 밀도를 낮춘다.

## 17. 통신사 데이터 판단

통신사 유동인구 데이터는 지역 단위 혼잡도에는 활용 가능할 수 있으나, 현재 확보된 API/계약이 없고 개별 순환버스 승객 수를 직접 나타내지 않는다.

따라서 본 버전에서는 통신사 기반 혼잡도 기능을 구현하지 않는다.

향후 학교/통신사와의 공식 제휴 데이터가 확보되는 경우 별도 요구사항으로 추가한다.

## 18. 테스트/인수 기준

### AC-001 광고

- 새 브라우저 세션에서 대형 광고 영역이 1회 표시된다.
- 닫은 뒤 같은 세션에서 재표시되지 않는다.
- 하단 얇은 배너는 항상 예약되어 있다.
- 안내 중에도 배너와 안내 UI가 겹치지 않는다.

### AC-002 ETA

- 배차시간이 있는 동안 다음 버스 예상시간을 표시한다.
- 실제 GPS가 아닌 경우 이를 명시한다.

### AC-003 Guidance

- 버스 경로 카드에서 안내 시작 가능.
- 승차 접근/도착/하차 접근 알림 상태 전환 가능.
- 종료 시 geolocation watch가 해제된다.

### AC-004 Crowd telemetry

- 동의 전에는 `/api/telemetry` 요청이 발생하지 않는다.
- 동의 후 탑승 중에만 주기적으로 업로드한다.
- 서버는 TTL이 지난 위치를 반환하지 않는다.

### AC-005 혼잡도

- 신고가 없으면 `정보 없음`.
- 신고 후 집계 API에 반영.
- 만료 후 집계에서 제거.

### AC-006 PM

- PM 레이어 토글 가능.
- 신뢰 가능한 데이터만 표시.
- 정확하지 않은 포인트는 `현장 확인 필요`로 표시.

### AC-007 2페이지/유용한 사이트

- BUS@YU와 유용한 사이트 페이지를 전환할 수 있다.
- 사이트 아이콘이 한 행 4개로 표시된다.
- `data/useful-sites.json` 수정 후 새로고침하면 반영된다.
- 관리자 페이지가 존재하지 않아도 운영 가능하다.

### AC-008 사용자 수/사이트 광고

- 동일 브라우저의 반복 새로고침이 오늘/이번달 수치를 계속 증가시키지 않는다.
- 오늘/이번달 통계가 사이트 페이지 하단에 표시된다.
- 통계 바로 아래에 메인과 별도 광고 슬롯이 표시된다.
